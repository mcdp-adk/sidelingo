# Decide every visual in one look module, with WinUI 3 values on Fluent UI

sidelingo must look like a native Windows 11 app, but it is built on Fluent UI React v9 (ADR 0003), whose defaults are Fluent 2 for the web. No maintained React library replicates WinUI 3, and Microsoft ships no WinUI theme for Fluent v9, so we keep Fluent UI and map WinUI 3's published values (microsoft-ui-xaml's theme resources) onto its tokens. Every visual decision lives in the look module: colour, transparency, radius, stroke, type, focus, selection, scrollbars, and the browser behaviours a native window lacks. Other components style layout only and may name tokens, never literal values. Only the window background is transparent, to show Mica; every surface above it is opaque, because Fluent gives controls and overlays one shared background token, and translucent overlays proved unreadable. Fixing the look one component at a time missed something every round; with one module, each fix lands everywhere.

**Considered options.** `react-windows-ui`: unmaintained since 2024 and untested on React 19. Hand-built controls: they would rebuild keyboard and accessibility support that Fluent already has. Translucent control fills, as WinUI uses: overlays share their token, and over Mica the opaque values look the same.
